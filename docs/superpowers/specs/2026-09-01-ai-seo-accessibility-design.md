# AI SEO Multi-Provider and Contrast Remediation Design

## Purpose

Restore resilient AI SEO generation when any supported provider is configured, while preserving the existing API and Filament form contracts. Remediate every audited use of the inaccessible orange text token on light backgrounds without changing the brand palette or unrelated dark-surface uses.

## Scope

- Add Anthropic, OpenAI, xAI/Grok, and Google Gemini adapters for AI SEO generation.
- Resolve configured providers with system-level preference and runtime fallback.
- Configure provider keys and models through Filament Settings with `.env` fallbacks.
- Preserve the exact successful `POST /api/admin/posts/generate-seo` five-field response and its 422 error shape.
- Replace audited light-surface text uses of `C.secondary` / `text-secondary` / `#df8448` with the existing accessible rust tokens.
- Do not deploy, run production PageSpeed, alter the primary orange token, or add per-request provider selection.

## AI SEO Architecture

### Provider contract

Create `App\Contracts\AiSeoProvider` with:

- `name(): string` — stable identifier: `anthropic`, `openai`, `grok`, or `gemini`.
- `isConfigured(): bool` — true only when both a non-empty API key and an available model are present.
- `generate(string $prompt): array` — returns exactly `seo_title`, `focus_keyphrase`, `meta_description`, `social_title`, and `social_description` as strings.

Provider implementations reside in `app/Services/AiSeoProviders/`. They own authentication, vendor request construction, structured response extraction, JSON decoding, and strict five-field normalization. Anthropic retains the existing SDK transport. The other adapters use Laravel's HTTP client to avoid adding new SDK dependencies.

### Resolver and fallback

`AiSeoGeneratorService` keeps its public `generate(string $title, ?string $content, string $contentType = 'blog'): array` signature and existing prompt rules. It receives/constructs the provider list, selects configured providers, and calls them in order:

1. `auto`: Anthropic → OpenAI → Grok → Gemini.
2. A specific `ai_seo_provider` value moves that provider to the front, then tries the remaining configured providers if it fails.

A failed provider is logged with a provider identifier and sanitized category only. The resolver continues to the next candidate. It raises a safe configuration message when no provider is configured, or a safe temporary-unavailable message after all configured providers fail. API and Filament callers never receive raw provider response bodies, credentials, prompts, or low-level exception messages.

### Configuration

Each provider reads a database Setting first, then its `config('services.*')` environment-backed fallback:

| Provider | DB key | Environment key | Model setting/environment |
|---|---|---|---|
| Anthropic | `anthropic_api_key` | `ANTHROPIC_API_KEY` | `anthropic_model` / `ANTHROPIC_MODEL` |
| OpenAI | `openai_api_key` | `OPENAI_API_KEY` | `openai_model` / `OPENAI_MODEL` |
| xAI | `xai_api_key` | `XAI_API_KEY` | `xai_model` / `XAI_MODEL` |
| Gemini | `gemini_api_key` | `GEMINI_API_KEY` | `gemini_model` / `GEMINI_MODEL` |

`ai_seo_provider` accepts `auto`, `anthropic`, `openai`, `grok`, and `gemini`, defaulting to `auto`.

Anthropic has a deliberate backwards-compatible exception: when no database or environment model is configured, it falls back to **`claude-sonnet-5`**, as explicitly approved. This is a compatibility fallback only, not a claim that the model is current. OpenAI, xAI, and Gemini have no hard-coded model defaults and therefore require explicit configured model names.

The resolver relies on `Setting::get()`'s observer-invalidated cache and does not add a second per-key TTL cache, avoiding stale settings after a save.

### Admin Settings UI

Extend the existing Filament `ManageSettings` page with an **AI Settings** tab:

- Preferred provider select (`auto` plus four providers).
- Four masked API-key inputs.
- Four model-name inputs.
- Read-only configured/active-provider status.
- Help text explaining DB-over-environment precedence and that blank model fields require an environment model except for the approved Anthropic fallback.

AI secret fields must not be returned by the public Settings API. Values stay within the existing Setting storage model; this change does not introduce a broad encryption migration or unrelated access-control refactor.

## API and Error Handling

The route, validation rules, HTTP 200 JSON shape, and direct service signature remain unchanged. The existing REST controller and Filament post editor keep their current happy paths. Failures keep HTTP 422 and `{ "message": "..." }`, but use stable non-technical messages generated by the resolver.

## Tests

Add focused backend tests using mocks/fakes only:

- one configured provider at a time;
- `auto` priority and selected-provider-first behavior;
- skip unconfigured providers;
- fallback after a provider error;
- safe messages for no configured provider and all-provider failure;
- Setting-over-environment resolution;
- exact five-string response normalization;
- existing controller authentication, authorization, validation, successful payload, and 422 shape remain covered.

No automated test makes a real vendor request.

## Accessibility Remediation

`C.secondary` / `#df8448` ranges from 2.55:1 to 2.79:1 against the audited light backgrounds and fails AA normal-text contrast. The existing `C.rust` (`#8f4a1f`) ranges from 6.07:1 to 6.63:1; Tailwind `text-rust` (`#a8551a`) ranges from 4.83:1 to 5.28:1. Both pass AA on the affected light surfaces.

Change only text and hover-text usages on light backgrounds:

- `frontend/components/HomePage.tsx`: hovered breed name, both Explore All links, Practical Difference eyebrow, Breed Banners Explore text, and post-card hover/read text.
- `frontend/app/dogs/[slug]/page.tsx` and `frontend/app/solutions/[slug]/page.tsx`: Read Guide text.
- `frontend/components/BlogPostPage.tsx`: first-letter decorative text and Read Story link.
- `frontend/components/ContactPage.tsx`: contact labels.
- `frontend/components/shop/ProductCard.tsx`: default Add to Cart text only; retain orange background/border and ink hover text.
- `frontend/components/FaqsPage.tsx` and `frontend/components/LegalPageLayout.tsx`: light-surface hover text.

Do not change `C.secondary`, `secondaryText`, their background/border/dot/gradient uses, icons outside the text-remediation scope, dark-surface orange text, or the unused HomePage ghost button variant.
